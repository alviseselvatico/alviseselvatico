# Architectural / Product Decisions

Keep this file short. Add a dated entry when a material decision changes.

## 2026-09-09 — D001 — Modular monolith first
Decision: build a local Python modular monolith before distributed services.
Reason: fastest path to test the ranking/editorial hypothesis.

## 2026-09-09 — D002 — Rights gate is a domain primitive
Decision: source rights policy is mandatory and defaults to block.
Reason: rights cannot be bolted on after automated ingestion/publishing.

## 2026-09-09 — D003 — Human-in-the-loop publishing
Decision: no autonomous public publication in early phases.
Reason: rights, factual accuracy, quality and channel risk.

## 2026-09-09 — D004 — FFmpeg as deterministic rendering core
Decision: use FFmpeg/ffprobe for the base renderer.
Reason: reproducibility, cost, portability and control.

## 2026-09-09 — D005 — Provider abstraction
Decision: transcription, LLM, evidence retrieval and publishing use adapters.
Reason: pricing and model capabilities change rapidly.

## 2026-09-09 — D006 — Data before ML
Decision: begin with heuristics + structured LLM features; collect labels before training bespoke models.
Reason: custom ML without quality labels is premature.

## 2026-09-09 — D007 — English-first content experiment
Decision: initial owned media experiment is designed for English-language verticals.
Reason: larger reachable audience and broader monetization/distribution options; not a limitation of core software.

## 2026-09-09 — D008 — Claude Code builds the system, not necessarily every production inference
Decision: Claude Code is the primary development agent. Production routing may use cheaper/specialized models.
Reason: reduce operating cost and avoid architecture coupling.

## 2026-09-09 — D009 — Rights policy invariants live in the domain model
Decision: `basis_type` governs the capability flags. `BLOCKED` and `UNKNOWN` force every `can_*` flag to false; `TRANSFORMATIVE_REVIEW_REQUIRED` forces `can_publish=false` and `review_required=true`. The invariant is enforced by the `RightsPolicy` model validator and covered by tests; the gate then checks flags only.
Reason: two sources of truth (basis type vs flags) would let a mis-entered record pass the gate.

## 2026-09-09 — D010 — Phase 0 fact check is human-only
Decision: in Phase 0 every claim generated by VME is created `UNVERIFIED` and blocks the draft (`blocked_factcheck`) until an operator marks it `HUMAN_APPROVED` or `REMOVED`. No evidence-retrieval adapter until Phase 1.
Reason: proves the gate mechanics without building retrieval before the ranking hypothesis is tested.

## 2026-09-09 — D011 — Transcription: local faster-whisper first
Decision: the first transcription adapter is `faster-whisper` (local, CPU/GPU), word-level timestamps, no diarization in Phase 0. Provider and model size come from configuration. A hosted STT adapter (with diarization) is a Phase 1 option behind the same interface.
Reason: zero API cost, no key, reproducible outputs, adequate for English long-form; diarization is not needed for the Phase 0 exit criteria.

## 2026-09-09 — D012 — LLM routing: two tiers via aliases
Decision: the LLM adapter exposes two aliases, `cheap` and `strong`, resolved from environment configuration (`VME_LLM_PROVIDER`, `VME_LLM_MODEL_CHEAP`, `VME_LLM_MODEL_STRONG`). First provider implementation: Anthropic Messages API with structured JSON output validated by Pydantic. No model ID in code.
Reason: matches the cost funnel; keeps D008 (Claude Code builds, production may route elsewhere).

## 2026-09-09 — D013 — Phase 0 reframe: blurred-background letterbox
Decision: 16:9 sources are rendered at 1080x1920 as a centered source layer over a blurred, scaled copy of itself. No speaker tracking, no face detection, no smart crop in Phase 0.
Reason: deterministic, one FFmpeg filter graph, no ML dependency; smart reframing is a measured Phase 2+ improvement.

## 2026-09-09 — D014 — Phase 0 commentary is text-only
Decision: original editorial value in Phase 0 is delivered as hook card + burned-in captions + optional text overlays. No TTS narration, no synthetic voice, no generated video.
Reason: avoids a TTS adapter, a voice choice and synthetic-media disclosure obligations before the pipeline is validated.

## 2026-09-09 — D015 — Tooling
Decision: `uv` for environment and lockfile, `ruff` (lint + format), `mypy --strict` on `src/`, `pytest`. Python 3.12+. Single `pyproject.toml`.
Reason: one fast, reproducible toolchain; avoids ad-hoc choices across sessions.

## 2026-09-09 — D016 — Test fixtures
Decision: audio/video fixtures for probe/render tests are generated at test time with `ffmpeg -f lavfi` (never committed). One short operator-owned speech clip (<= 90 s, WAV, `OWNED` policy) is committed under `fixtures/speech/` via an explicit `.gitignore` allow rule, and is the only committed media in the repository.
Reason: `.gitignore` blocks media by default; transcription tests need real speech; everything else is reproducible.

## 2026-09-09 — D017 — Source supply is a Phase 1 entry condition
Decision: Phase 1 (golden set) cannot start until at least 3 distinct authorized sources (OWNED, EXPLICIT_LICENSE or CREATOR_AUTHORIZATION) totalling >= 3 hours of English speech are registered with evidence. The operator maintains the list in `docs/SOURCES.md`.
Reason: 50-100 labeled candidates cannot come from one file; authorized supply is the real bottleneck, not code.

## 2026-09-09 — D018 — Phase 0 media registration references the operator's file in place
Decision: `media register` stores the resolved absolute path of the local file plus its SHA-256; it does not copy the file into `artifacts/source/`. Logs show only the file name unless the path is inside the artifacts directory. A permissive `basis_type` additionally requires a non-empty `basis_reference` at the model level (SOURCES.md rule: no evidence = `UNKNOWN`).
Reason: Phase 0 works on one local authorized file; duplicating gigabytes buys nothing, and the fingerprint detects a changed or moved file at the next step. Copying/object keys arrive with object storage (ARCHITECTURE §9).

## 2026-09-09 — D019 — Third-party speech fixtures are fetched, pinned and never committed
Decision: besides the operator-owned clip of D016, tests may use public-domain speech samples downloaded by `scripts/fetch_speech_fixtures.py` into git-ignored `fixtures/speech/external/`. Each manifest entry pins URL, SHA-256 and rights evidence. Tests skip with an explicit reason when no fixture is present. Public-domain status is evidence for *test* use only; registering such a file as a VME source still needs an operator-confirmed `RightsPolicy`.
Reason: no operator recording exists yet; CLAUDE.md forbids committing downloaded third-party content; a pinned hash keeps transcription tests reproducible.

## 2026-09-09 — D020 — Transcription and segmentation are gated on `ingest`
Decision: `transcribe` and `segment` re-evaluate the rights gate with action `ingest` (the policy may have expired since registration) and require the file to still match its registered SHA-256. `clip` is checked when a candidate is extracted/rendered, `render_transform` when editorial content is applied, `publish` never before Phase 3.
Reason: transcribing and finding boundaries produce internal analysis artifacts, not clips; tying them to `ingest` keeps the four flags meaningful and avoids blocking analysis of sources whose clip rights are still under review.

## 2026-09-09 — D021 — Ranking funnel mechanics and Phase 0 cost accounting
Decision: `rank` runs the CLAUDE.md funnel as: deterministic prefilter (duration and word-count feasibility limits, not rights rules) -> `cheap` alias on every survivor only when survivors exceed `finalists_k` -> `strong` alias on the finalists. The strong score is decisive; if the strong call fails, the cheap score is kept and the failure is written into the run's rationale and its own `LlmCall` row. `rights_risk` is derived in code from the policy basis (OWNED/EXPLICIT_LICENSE/CREATOR_AUTHORIZATION 0.0, PUBLIC_DOMAIN_VERIFIED 0.1, TRANSFORMATIVE_REVIEW_REQUIRED 0.6). Score ranges are validated in code, so the JSON schema sent to the provider carries no numeric constraints. `estimated_cost_usd` stays `NULL` in Phase 0: token usage is persisted per call and pricing is applied at reporting time, never hard-coded.
Reason: a cheap pass over five candidates costs more than it saves; keeping the cheap score on a strong failure preserves a ranking with visible provenance instead of silently dropping a candidate; pricing tables change faster than code.

## 2026-09-09 — D022 — Editorial generation, claim union and review mechanics
Decision: `editorial generate` makes two structured calls: the Editorial Transformer (`strong`) produces the text-only draft (D014) plus the claims it knows it introduced; the Claim Extractor (`cheap` when configured, else `strong`) independently re-reads the generated text. The union of both lists, de-duplicated on normalized text, becomes `Claim` rows, every one `UNVERIFIED` (D010); a draft with at least one claim starts in `blocked_factcheck`, otherwise in `needs_review`. Generation is gated on `render_transform`. Approval re-runs the fact-check gate and the rights gate (`clip` + `render_transform`) at decision time and a block wins over the operator's approval. Rejection requires at least one reason code. Operators may only set `HUMAN_APPROVED` or `REMOVED` in Phase 0; reviewer identity comes from `--reviewer` or `VME_REVIEWER` and is mandatory. `EditorialVersion` stores `commentary_before`/`commentary_after`, `excerpt_plan`, `title_options` and `transformation_summary` (contract §2) instead of a single `commentary`; claims live in their own table rather than `claims_json`.
Reason: the transformer under-reports its own claims, a second reader is cheap; a stale approval is a rights/fact risk; reason codes are the labels Phase 1 needs; separate claim rows make per-claim audit possible.

## 2026-09-09 — D023 — Generative video providers (e.g. Higgsfield) deferred to Phase 2+
Decision: no generative-video API (Higgsfield, or the Sora/Veo/Kling models it fronts) in Phase 0-1. If ever adopted it enters as an `editorial visuals` adapter behind the provider interface (D005), only for B-roll/hook-card motion around the authorized excerpt, with the synthetic-content disclosure flag stored in publication metadata (guardrails §8) and a per-day cost cap (guardrails §10).
Reason: it is generated media, excluded by D014 and the roadmap; it is non-deterministic and credit-billed, so it breaks reproducibility of the render from a stored `RenderPlan` (D004) and adds cost before the ranking hypothesis is tested; platform reused/inauthentic-content rules make heavy AI visuals a risk, not a lever, until original editorial value is proven with text-only drafts.

## 2026-09-09 — D024 — Ranking tiers are not comparable; finalists always rank first
Decision: `RankingRun.tier` records which stage produced the decisive score (`strong`, `cheap`, `prefilter`). A batch is ordered by tier first (strong-scored finalists, then cheap-only candidates, then prefiltered), and by `final_score` inside a tier. Downstream selection (`pipeline run --top`, editorial) reads that order.
Reason: the first real run (LibriVox chapter, 26 candidates) showed Opus scoring the finalists 31-54 while Haiku scored non-finalists around 60; a single sorted list mixed the scales and pushed every finalist below rank 12. Component vectors of both tiers stay persisted for Phase 1 calibration.

## 2026-09-09 — D025 — Cost is reported from stored usage, and stated as a lower bound
Decision: `vme report cost` aggregates the token counts recorded on every `LlmCall` and applies a versioned price list (`src/vme/reporting/pricing/anthropic_v1.json`, override with `VME_PRICING_PATH`); no price is hard-coded (D021). A model id the list does not know is reported in `unpriced_models`, never costed at zero silently; a dated snapshot (`claude-haiku-4-5-20251001`) resolves to its base model, matching only on a `-` separated suffix. Attempts rejected by schema validation are billed by the provider but their usage never reaches us (the SDK raises before the usage block), so the report counts them in `unmetered_attempts` and flags the total `is_lower_bound`.
Reason: the first real run silently under-reported Haiku at $0 because the API returns the dated snapshot while configuration names the alias. A cost figure that is quietly wrong is worse than one that says how wrong it can be.

## 2026-09-09 — D026 — Roadmap order and the Phase 4 acceptance test
Decision: Phases 6 (B2B creator product) and 7 (distribution network) become the last, ancillary phases; they never gate Phases 1-5. After Phase 4, the engine is accepted by feeding it macroeconomic long-form content and verifying that it produces a short ready for multi-channel publication (rights and claims cleared, render valid per target format, metadata reviewed). Platform adapters beyond YouTube stay in Phase 5.
Reason: operator decision. The internal engine and its predictive validity come first; macro/markets is one of the initial verticals and the one with the strictest factual controls, so it is the hardest honest test.

## 2026-09-09 — D027 — Labels are append-only rows with a versioned reason taxonomy
Decision: human labels on candidates (`labels` table) carry the seven DATA_MODEL §3 dimensions and are append-only; the golden set takes the latest label per (candidate, reviewer) and aggregates across reviewers (majority decision, ties reject; mean of graded fields). Rejection reasons, for labels and for `review reject`, must come from a versioned taxonomy file (`src/vme/labeling/taxonomy_files/reasons_v1.json`); `other` requires a note. Ranking benchmarks are persisted (`benchmarks` table) with scoring, weights and prompt versions so `bench compare` can flag a regression when any of them changes.
Reason: Phase 1 exit criteria need labels a model can learn from and a benchmark that notices change; free-text reasons and unsaved metrics give neither.

## 2026-09-09 — D028 — Provisional labels bootstrap the golden set and yield to human labels
Decision: a label may be flagged `provisional` (machine-generated or draft). Provisional labels are stored like any other, but the golden-set aggregation ignores them as soon as at least one non-provisional (human) label exists for the candidate. Benchmarks and exports report the provisional share, and the Phase 1 exit size (50 labeled candidates) counts human-labeled candidates only. Provisional labels carry the reviewer identity of the model or session that produced them.
Reason: a benchmark against machine labels measures model agreement, not human agreement; it is useful to bootstrap and to smoke-test the harness, and harmful if it is ever mistaken for the human golden set. The flag keeps the two apart in the data instead of in someone's memory.

## 2026-09-09 — D029 — Bootstrap supply for the provisional golden set
Decision: for the provisional golden set the operator authorised a reduced supply bar: at least 3 distinct public-domain or explicitly licensed sources totalling at least 1 hour of English speech, macro/economics vertical where possible, transcribed with the `base` model for throughput. D017 (3 sources, 3 hours, human labels, evidence) remains the bar for the human golden set and for Phase 1 exit.
Reason: operator decision to size the bootstrap pool to the available compute; a 1-hour pool already yields ~100 candidates at the default 35 s target.

## 2026-09-09 — D030 — Automated fact check: evidence retrieval and the human-confirmation policy
Decision: Phase 1 adds an evidence retriever behind a small interface (first adapter: Anthropic web search, strong tier) and a structured Fact Check Evaluator (PROMPT_CONTRACTS §4). Retrieved items are persisted as `evidence` rows; every retrieval and evaluation is an `LlmCall`, with web searches counted and priced. The evaluator's verdict is applied to `Claim.status` under a policy: `CONTRADICTED` and `AMBIGUOUS` are set as such (both block); `INSUFFICIENT` leaves the claim `UNVERIFIED`; `SUPPORTED` resolves the claim only when it lists at least one valid evidence id (guardrails §7) and the claim's importance is not in `VME_FACTCHECK_HUMAN_IMPORTANCE` (default `HIGH`), otherwise the verdict is recorded in `machine_status` and the claim stays `UNVERIFIED` for a human. Humans still only set `HUMAN_APPROVED`/`REMOVED` and may override any machine verdict. Every machine verdict is a `ReviewEvent` by `factcheck_evaluator:<version>`.
Reason: D010's human-only rule was a Phase 0 simplification; the finance/macro vertical needs heightened verification of material claims (guardrails §6), so the machine may clear low-stakes claims and must not clear high-stakes ones alone.

## 2026-09-09 — D031 — Deterministic boundary editor before any LLM boundary editing
Decision: a pure boundary editor (`boundary_editor:v0.1.0`) aligns spans to sentence boundaries from word timestamps and punctuation, drops boilerplate and section markers at the edges, and never touches the interior. The segmenter (now `v0.2.0`) applies it in trim-only mode at creation; `candidate refine` applies it with bounded extension to existing sets, writing derived candidates (`derived_from_id`) so originals, rankings and labels stay intact. The LLM Candidate Boundary Editor of PROMPT_CONTRACTS §5 remains a later, optional step for cases punctuation cannot resolve.
Reason: the bootstrap golden set showed edge fragments as the most common defect; punctuation and timestamps already solve most of them deterministically and for free.
